# Structured automation v1 architecture proposal

Baseline: vivi-cli main b98b8b879f0927fa0f4e52f00a8a1b79215a4706, core 0.17.0. Reference: Codex rust-v0.166.0 sdk/typescript/README.md. This change belongs in CLI; no core release needed.

## Entry and compatibility
- New opt-in `--jsonl` requires `--prompt TEXT`; optional `--output-schema PATH` requires `--jsonl`. No new interactive surface, SDK, stdin prompt protocol, output file manager, permission mode, or provider transport.
- Existing plain/TUI paths unchanged. Launcher detects JSONL before Bun selection, even on a TTY. `--tui`, interactive enrollment modes, `--help`, auth/MCP subcommands and input diagnostics combined with JSONL are usage errors, so every JSONL invocation has the same envelope rather than mixed help text.
- Prompt is literal provider input in JSONL. It bypasses `runChatLoop` slash handlers and `sendChatTurn` !shell/steering interpretation. A resumed session must not replay retained queued input (reject pending queue before dispatch rather than drop it). Non-JSONL `--prompt` keeps its historical behavior.
- Noninteractive Manual permissions only: questions unavailable, approvals denied, MCP servers remain disconnected, no auth/setup dialog or fresh Auto/Skip enrollment. Explicit nonmanual request fails usage rather than silently downgrades. Existing safe workspace reads continue; no privilege expansion.

## Wire contract
- UTF-8, one compact JSON object per newline; stdout is protocol only. No ANSI/OSC/title/spinner/banner/raw provider stdout. Stderr is bounded redacted diagnostic text; no stdout fallback. Consumers must drain both streams.
- Every record has `protocol:"vivi.automation"`, `version:1`, opaque `run_id` UUID, monotonically increasing `seq` starting1, and `type`. No timestamp required, simplifying deterministic tests.
- `run.started`: first record, before argument/schema validation once runtime/module bootstrap succeeds (bootstrap failures may have no envelope); no prompt, cwd, account ID or session history. `session.started`: session_id after successful locked load/create/initialization, provider/model identifiers redacted; session ID enables explicit resume.
- `assistant.completed`: accepted complete assistant text, round counter, tool-call count. In schema mode omit text entirely until the validated successful terminal record; emit only metadata. Do not emit provider state, reasoning or transient text deltas. `tool.started`: redacted name and call_id; arguments omitted. `tool.completed`: same identifiers, is_error boolean; result bodies/images omitted. Tool completion means execution report, not transactional effect/whole-run success.
- `round.completed`: round number, usage object or null. `context.compaction.started/completed/failed`: fixed safe reason/code metadata and bounded numeric measurements only. Unknown core event variants are ignored rather than leaked.
- `approval.denied`: fixed reason `interaction_required`, no description/raw args; deny immediately and record attempted interaction. This classification covers actual approval callbacks only. Host paths that reject unavailable command/question/MCP surfaces before requesting approval remain ordinary tool errors; the agent may handle them. A completed run means the agent completed, not that its semantic goal was achieved. If an actual approval callback was denied, terminal status is interaction_required even if the agent later completes.
- `run.completed` terminal includes exit_code0, session_id if available, final_text, optional structured_output, rounds, reported usage aggregate and explicit complete_usage boolean (all committed provider rounds supplied usage). Zero reported counts do not assert zero billing. Summary usage is separate or omitted from this turn aggregate with docs.
- `run.failed` includes stable code, exit_code, generic safe message, optional session_id, rounds/usage if available; no raw thrown object/stack/provider payload. `run.cancelled` includes reason signal and130/143. Exactly one terminal record after all normal cleanup, including session lock release; healthy-output startup failures also get terminal failure.
- Missing terminal record means incomplete/unknown outcome regardless of prior accepted events. Consumers require terminal success AND process exit0. A final write may fail after bytes partially escape; do not promise atomic delivery or success on broken stdout.

## Exit/status precedence
JSONL-only codes: 0 completed; 1 runtime/provider/storage/cleanup failure; 2 invalid CLI/schema/config; 3 final output invalid/schema mismatch/redaction conflict; 4 interaction required; 74 output I/O failure; 130 SIGINT;143 SIGTERM. Expected AbortError caused by the wrapper’s already-recorded cancellation preserves cancellation rather than runtime1; genuine cleanup failures still override. The first SIGINT/SIGTERM wins; repeats do not change its exit code or force immediate process.exit. Known core reason (e.g. max_rounds) appears as machine failure code, not parsed human text.
Precedence: output failure > cleanup/runtime failure > cancellation > interaction required > schema failure > success. Usage errors occur before state/provider work. Completion is stored until main's finally has fully settled, then finalized by the automation wrapper. Existing plain exit behavior unchanged. Uncatchable termination cannot produce a terminal guarantee.

## Schema output
- Load local regular file only, max64KiB, UTF-8 JSON; max JSON depth32,256 syntactic schema nodes,16 branches per combinator,16 reference hops and2048 expanded schema visits (count every referenced subtree for every use before AJV compile); validate/compile before session/catalog/provider work. Reject secret-bearing schema before transmission; recheck against the current dynamic secret list immediately before every provider estimate/generate after selected auth registration. File/schema syntax/compile/unsupported/budget errors are exit2 before state work; no raw path/compiler details in protocol. No remote reference fetches, no dynamic code/custom validators from files.
- Use pinned mature Ajv8.17.1 (release older than seven days) with JSON Schema draft2020-12 strict validation. Explicit supported subset: type, properties, required, additionalProperties, items/prefixItems, min/maxItems, min/maxLength, minimum/maximum/exclusiveMinimum/exclusiveMaximum/multipleOf, enum/const, anyOf/allOf/oneOf/not, title/description/default/examples, $schema/$defs/$ref. Optional $schema must be exactly https://json-schema.org/draft/2020-12/schema; reject $id so it cannot change base resolution. Only fragment-only same-document acyclic refs; reject pattern/patternProperties/format, recursive/dynamic refs, unevaluated and other unsupported keywords; do not silently ignore constraints. Boolean schemas supported. Bound branching and references to avoid exponential expansion. Document limitations as a portable structural subset, not full-dialect conformance.
- Provider wrapper adds an ephemeral system instruction/schema to normal response requests and all context estimates (the estimate API has no purpose; summary estimates are conservatively high), never to context-summary generation requests; only original user prompt remains canonical. Tool rounds remain possible. Tell provider final response must be one JSON value with no fences. No extra repair/provider rounds beyond the configured normal agent loop.
- On completed run, parse exact final content, bound256KiB UTF-8 and decoded depth128, validate final JSON against compiled schema. Refuse success if secret filtering would change JSON keys or values; structured data withheld with stable output_redacted code. For valid safe JSON emit parsed structured_output plus final_text. No stringification coercion/default insertion/removal of properties. Invalid JSON, invalid schema result and output-too-large are distinct safe codes without echoing offending values/schema validation details.
- This is prompt guidance + local verification across current providers, NOT provider-native constrained generation. Schema is sent to the selected provider; schema file itself is not saved or persisted as a new preference.

## Ownership, output and redaction
- AutomationIO implements ChatIO but has no stdin/readline/TTY hooks. Dedicated wrapper owns process SIGINT/SIGTERM listeners from startup to final cleanup, an AbortController/cancel listeners, JSONL sink, and terminal result decision. Runtime dependencies expose output streams and injected cancellation to make tests deterministic without real signals/accounts.
- JSONL sink serializes writes, awaits callback/backpressure on event writes; change ChatIO.event signature to void|Promise<void> and return it from main's CliHost.onEvent. Bound encoded record4MiB and total queued bytes4MiB (both final_text and structured_output plus worst-case JSON escaping fit the256KiB final bound); reject any encoded-record overflow as output error74, never clip and succeed; no unbounded queue. Every error/close/timeout while output is pending aborts provider/host and returns74. Stalled output deadline is documented (e.g.30s) so pending output promises reject and owned host cancellation/drain can proceed rather than waiting forever for the consumer; no deadline claims a host with unverified cleanup is clean; tests inject clock/short deadline.
- Main's synchronous notices go to bounded stderr, never enqueue unlimited stdout. Stderr write failure aborts with output failure too; retain a sink error listener until pending writes settle to avoid unhandled late EPIPE.
- Full-text accepted records use current dynamic known-secret list; no transient chunk leak. Omit unnecessary identifiers/args/results rather than redact giant nested payloads. Escape JSON with JSON.stringify. Secret screening happens before output with limits; initial env credentials + newly registered selected auth/MCP secrets flow to the adapter. No promise to discover unknown secrets or to retract output if a new secret is registered later.
- Terminal emission happens outside mainInner after its existing finally. Capture exceptions from auth close/io close too. Preserve existing unconfirmed-cleanup lock retention and never convert failure to success. No signals cause immediate process.exit.
